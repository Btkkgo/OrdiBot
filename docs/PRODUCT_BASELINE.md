# OrdiBot V1 product baseline

[English](PRODUCT_BASELINE.md) | [简体中文](PRODUCT_BASELINE.zh-CN.md)

Effective 2026-10-12. The owner's approved OrdiBot V1 direction replaces every historical financial, Android-autonomy and standalone desktop-pet product definition. The current scope is **Your Desktop AI Companion**: Chat Window, Context Assistant, Remote Agent Workspace.

Chat uses a compact dark floating window, narrow Chat/Context/Agent/History/Models/Settings navigation, soft white text, rounded input, and a small original 2D character next to the window. The character stays beside expanded Chat and returns to an edge head when Chat is collapsed or closed. Only an explicit Hidden action removes the desktop entry. Agent expands the same native window into a dark workbench with a restrained purple gradient, real status and collapsible provider records. Returning to Chat restores its geometry. No separate pet runtime, financial dashboard, local autonomous computer engine or cloud VM implementation is in scope.

The owner-approved supplemental direction adds four surfaces: Hidden, Edge Pet, Chat Expanded and Agent Workspace. Startup shows a small clickable, partially clipped edge head (about 44–56 px visible); collapse/close returns to its remembered left/right edge and vertical position. Clicking opens Chat from that edge while keeping the character visible. No desktop roaming or complex pet engine.

Layer A passively detects only app name/window title and timestamp for optional lightweight reminders. Throttle at 20 seconds, deduplicate repeated app/title pairs, allow disabling and browser/editor filtering. It never reads page body, clipboard, screen pixels or accessibility content. Clicking a reminder opens Chat, attaches only the actual metadata and focuses the input. An explicit content card offers copied-text or preview-confirmed screenshot attachment for questions about the body; app/title metadata never implies page understanding. Layer B deliberately obtains copied text or confirmed screenshots. Missing permissions degrade to manual attachments. Reference image 3 was not received; settings follow the supplied text direction, not an unseen-image claim. Attached material is untrusted source data. The model must never claim access to a screen or file it did not receive.

Ordinary model requests use the existing Model Gateway and OpenAI-compatible API. Configuration includes Provider, Base URL, system-secured API Key, Model ID, vision and output limit. Default system behavior answers the actual question directly in 1–3 sentences, without independent research unless requested. Concise/Normal/Detailed are selectable. Streaming, cancellation, timeout and retry errors remain explicit. Production has no mock answers.

Remote computer work is delegated to a documented hosted provider; ordinary model chat and opening a service webpage do not constitute remote-computer integration. Status, records, approvals and results must come from the provider. Only supported controls are shown. The initial OpenAI adapter supports public read-only browser tasks and origin approval, not sign-in or custom tool execution. Uncertain submissions are not automatically repeated. Review the service's permissions, current prices and account limits locally.

macOS Apple Silicon is the first delivery platform; Windows is independently compiled/tested. Local ad-hoc signing is allowed; Apple Developer, notarization, App Store and commercial distribution are out of scope. Chinese collaboration and current UI; important public records are English-primary with Chinese counterparts. English interface localization is deferred.

Preserve the original repository, refs, stars, Issues/PRs, private SQLite, credentials and separate physical robot project. Rename the same repository to OrdiBot; never recreate it or rewrite history. New product storage explicitly preserves the legacy namespace. Retired code remains recoverable but is excluded from the default native/frontend runtime.

**Acceptance boundary:** the owner deferred real Chat/vision/hosted-Agent API acceptance until local credentials are configured. UI, local platform checks and adapter tests proceed; G2/G3 must not be called fully verified. Windows compilation is distinct from Windows interactive/API acceptance. See [current status](CURRENT_STATUS.md).
